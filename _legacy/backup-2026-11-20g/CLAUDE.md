# The Astral Forge: notes for the next AI

Documentation site for Alaxouche's Wabbajack modlists (theastralforge.com). There are five lists: Wunduniik and Krentoraan (Skyrim SE), Ghost of the Grid (Cyberpunk 2077), No Man's Sky Explorer, and Extrasolar Containment Protocol (Starfield). All content is bilingual EN/FR.

The site was **rebuilt in November 2026**. It no longer uses Jekyll. A small Node generator now reads the old Jekyll content (Markdown, YAML, Liquid) unchanged. The user speaks French.

## Commands

```bash
npm install          # liquidjs, marked, js-yaml (dev deps only)
npm run dev          # build + server on http://localhost:4000, rebuilds when files change
npm run build        # one-off build into _site/ (also refreshes _data/modlist_snapshot.json from the live modlist.json)
npm run check        # checks _site/: internal links/images/srcset exist, every <img> has alt, no hotlinked image
npm run thumbs       # python scripts/make-thumbs.py: 480 / 960 / 1600 px WebP (1600 at quality 85) + manifest (Pillow); run after adding images
npm run og           # python scripts/make-og.py: social preview cards in assets/og/ (after a build; run again when pages are added or renamed)
npm run hex          # python scripts/make-hexfield.py: the honeycomb backgrounds (numpy + Pillow), then npm run thumbs
npm run contents     # python scripts/modlist-contents.py [id] [local .wabbajack]: _data/contents_<id>.json from the PUBLISHED lists; run after each list release
```

- **The dev server does not reload `scripts/build.mjs`.** After editing that file, restart the server. On Windows, the old Node process often keeps port 4000 (`EADDRINUSE`). Free it with:
  `netstat -ano | grep ":4000 " | grep LISTENING` then `taskkill //PID <pid> //F`.
- Changes to templates, CSS, JS and content trigger an automatic rebuild (~0.8 s). Builds are **incremental**: `_site/` is never wiped, files are only written/copied when they changed, and anything the build didn't produce is deleted at the end (`pruneOut`). So a test file dropped in `_site/` disappears at the next rebuild. Builds never overlap (a change during a build queues one more).
- `site.version` (the `?v=` on site.css/js) is a hash of `site.css` + `site.js`, not a timestamp.
- `site.css` / `site.js` are minified by esbuild (dev dependency, exact version 0.28.2) when written to `_site/`; edit the readable sources in `theme/assets/`. `theme/static/_headers` sets Cloudflare Pages cache rules (patterns must not overlap: Cloudflare joins the values). The inline `<head>` script and `site.js` carry `data-cfasync="false"` so Cloudflare Rocket Loader cannot delay them (it made the language and theme switch after the first paint).
- Ruby/Jekyll is not installed and is no longer needed.
- Deployment: `.github/workflows/pages.yml` (Node 22, `npm ci`, thumbnails with Python + Pillow, `npm run build`, `npm run check` as a non-blocking report, uploads `_site/`). On pull requests: `quality.yml` (build + blocking `npm run check` + non-blocking lychee for external links) and `lighthouse.yml` (build, http-server, Lighthouse on home / overview / guide / changelog / FAQ). All three were moved off Jekyll in Nov 2026; `images.yml` (size budget) and `gallery-sync.yml` (weekly Discord sync) are unchanged.
- The first build after starting the dev server can take 3 to 50 s on this machine: the profile shows it is disk wait on G:, the build itself is about 1 s of CPU. Don't chase it as a code regression.

## Build-specific behaviour

- Layout mapping (`layoutFor`): `skyground_home` → home, `skyground_base` / `page` → page, everything else → doc.
- kramdown is emulated: `markdown="1"` is removed (CommonMark handles HTML blocks itself), and `{: .note }` / `{: .warning }` etc. become `.callout callout-*` (on the paragraph or the following blockquote).
- Heading ids are slugified with de-duplication. The `# h1` in the content is **hidden by CSS**; the doc layout shows its own title.
- Each modlist's front matter (`_<id>/index.md`) supplies `game`, `project_banner.{image, accent, subtitle, subtitle_fr, stats}`. The build exposes this as `site.modlists[]` with `nav` and `live` (fallback values taken from `_data/modlist_snapshot.json`).
- **Live data at build time**: `liveModlists()` fetches the live `modlist.json` once per process (8 s timeout, `TAF_OFFLINE=1` skips it) and refreshes the snapshot in memory, so the HTML carries current versions, sizes and dates. `npm run build` also rewrites `_data/modlist_snapshot.json` when it changed; the dev server never writes it (it would trigger a rebuild).
- The `Loading...` placeholders (`data-modlist-total/install/download`) are filled in at build time from the snapshot.
- **Thumbnails**: Liquid filters `{{ src | thumb: 480 }}` and `{{ src | srcset }}` read `assets/Images/_thumbs/manifest.json` and fall back to the original when a thumbnail is missing. Used by the screenshot grid (480), feature rows and the community gallery (960; the lightbox still opens the original through `data-zoom`), and `srcset` on the home panels, hub bands and page heroes.
- **YouTube**: `youtubeFacade()` turns `youtube.com/embed/<id>` iframes into a link with the local thumbnail `assets/Images/guides/yt-<id>.webp`; `site.js` swaps in a `youtube-nocookie` player on click. A new video needs its thumbnail saved there (otherwise the link shows without a picture).
- The `FR` dictionary in `build.mjs` translates titles and labels. Liquid filter `bi` → `<span lang="en">…</span><span lang="fr">…</span>`.
- `step` (guide page n / total) is computed from the parent page and its children (`parent: Installation Guide`). `step.items` carries `{title, url}` for the step bar labels.
- A first `h2` that repeats the page title (e.g. "System Requirements" under "System Requirements") gets `class="is-dup"`: hidden by CSS, skipped by the outline and anchors.
- Doc subpages use a compact hero (`.phero--compact`); only the modlist overview keeps the full-height one.

## Front end

- **Language**: `html[data-lang]` hides `[lang="en"|"fr"]` blocks. Choice stored in `localStorage['sg-lang']`, browser language by default. Every interface string must exist in both: `<span lang="en">…</span><span lang="fr">…</span>`. Attributes can't hold spans: put English in the attribute and French in `data-ph-fr` (placeholder), `data-aria-fr` (aria-label) or `data-title-fr` (title); `localizeAttrs()` in `site.js` swaps them.
- **Accessibility** (last CSS layer "Readability & accessibility"): text tokens meet WCAG AA (`--dim` 4.7:1, `--muted` 6.2:1, don't darken them), body weight 400, 2px gold focus ring (inset on `overflow: hidden` boxes), `prefers-reduced-motion` stops all loops, `prefers-contrast: more` and `forced-colors` handled. Mobile menu and docs sidebar go through `overlay()` in `site.js` (Escape, focus in/out, Tab trap, `aria-expanded`). Search announces its result count in `#search-status`. `.sr-only` exists for screen-reader-only text.
- **Theme**: dark by default, plus a light theme (Nov 2026) chosen with the sun / moon button next to EN/FR (`[data-theme-toggle]`, `localStorage['taf-theme']`, applied by the `<head>` script before paint, `html[data-theme]`). It does not follow the OS setting: dark stays the house look. How it works: translucent colours are rgb-triplet tokens (`--ink` lines/glass, `--paper` scrims, `--txt` soft text, `--white` strongest text, `--logo-filter`), and the last CSS layer redefines every token for `:root[data-theme=light]`. Image areas stay dark islands (they reset the dark tokens): home panels except The Forge, `.phero`, hub bands, `.doc-cta`, `.cta`, lightbox, video thumbnails, and the nav while it floats over a dark hero. **New CSS must use the tokens, not literal `rgba(255,255,255,…)` / `rgba(7,8,10,…)` / `#fff`**, or it breaks in light. Light palette contrast: `--fg` 13:1, `--muted` 6.9:1, `--dim` 5.5:1, `--gold` #7a5b22 5.6:1. Gold `--gold: #c9a96e`, background `#07080a`, font **Jost**, self-hosted in `theme/assets/fonts/` (latin + latin-ext variable woff2, SIL OFL, `OFL.txt`), the latin file is preloaded; `"Jost Fallback"` is Arial resized to Jost's metrics (values computed with fontTools) so the font swap doesn't move the page. No Google Fonts. **One colour for every modlist**: the build sets `modlist.accent` to `var(--gold)` (the per-list colours were removed at the user's request, Nov 2026; `project_banner.accent` in front matter is ignored). **No dash rule** before "Version" on the home panels.
- **Logo**: the emblem (circle + sword). Browser tab icon: `favicon.svg` (transparent, fills the square, white in a dark browser theme and dark in a light one through `prefers-color-scheme` inside the SVG) + `favicon-32.png` fallback; app icons (`emblem-180/192/512.png`) keep the dark background. All made by `make-emblem.py`. Source in `assets/source/emblem-source.png` (not deployed), assets regenerated with `python scripts/make-emblem.py assets/source/emblem-source.png assets/logos`: `emblem.webp` (large) and `emblem-mark.webp` (nav/footer), both transparent and lossless, `emblem-32/180/192/512.png` (favicon, apple-touch, manifest) and `emblem-og.jpg` (social card), white on the site background. The source is rendered with a glow: the script keeps only the solid strokes (luminance >= 252). **The user wants the plain logo, no glow, halo or drop-shadow**, in files and in CSS. The old `theastralforge.*` files are no longer referenced by the theme.
- **Visual identity** (asked for by the user, keep it): 4-point star (`.diamond` / `.star` via `clip-path`) instead of diamonds, rune decoding of titles (`[data-scramble]`), film grain (static since Nov 2026, `body::after`), animated "molten metal" bar. **No cursor halo**: removed at the user's request, do not add it back. **No roman numerals** on the home panels (I, II… and "Modlist II" labels), removed at the user's request (Nov 2026).
- **Modlist emblems** (Nov 2026): `scripts/make-modlist-emblems.py` draws `assets/logos/emblems/<id>.svg` in the site emblem's language (thick ring broken where the motif crosses it, plain white, no glow): Wunduniik snowy mountain with three pines standing on the ring and the North Star, Krentoraan tower, Ghost of the Grid broken grid with a glitched ring, NMS planet and orbit, ECP hexagonal field with clamps and the site star. The build sets `modlist.emblem`; the home panels show it centred at rest (`.panel__mark`) and small above the title when open (`.panel__logo--list`). The Forge panel gets one gold sheen across the honeycomb when it opens (`.panel__sheen`, fixed `vw` width, transform + opacity, runs once).
- **No particles**: the user asked (Nov 2026) to remove the ember / spark effects completely (first a Canvas 2D version, then a WebGL one). Do not add particle effects back unless asked.
- **Home**: 6 panels (`.panel`) driven by JS through `.hero.has-on` / `.panel.is-on` (hover on desktop, tap on mobile, arrow keys). They are **slanted** (asked by the user): each panel is a `clip-path` parallelogram overlapping the previous one by `--o` (about 5 degrees), with a gradient seam in `.panel + .panel::before`. On mobile they are horizontal bands slanted the same way (`--o: 16px`, vertical overlap). Content stays upright; elements near a slanted edge are offset by `--o`.
- **Honeycomb backgrounds** (asked by the user, Nov 2026), all from `scripts/make-hexfield.py` (variants listed in `VARIANTS`): The Forge panel has a rest + lit pair per theme (`forge-hex-dark/lit`, `forge-hex-light/light-lit`; `.panel__bg--d` / `--l` show the current theme's pair, `.panel__bg--lit` cross-fades by opacity when the panel opens; the light pair is `loading=lazy` so the dark theme never downloads it). `hex-hero.webp` is the hub header and the overview CTA strip, `hex-void.webp` (missing tiles) the 404 header, each with a `-light` twin: these honeycomb banners follow the theme (they are not dark islands in light; `.theme-d` / `.theme-l` classes show the current theme's picture, the light one is lazy). `page_hero.html` takes `hex=true` (class `.phero--hex`, no extra dimming) and `image_light`. Hero pictures with `fetchpriority` are never made lazy by `postProcessHtml` (they are the LCP). The old `AstralForge_Background_*.webp` remain the default page hero.
- **Social cards**: `scripts/make-og.py` reads `_site/search.json` and draws one 1200x630 JPG per page in `assets/og/<url with / as -->.jpg` (modlist pages: the list's screenshot darkened + gold; other pages: `hex-hero`), incremental through `assets/og/manifest.json` (bump `STYLE` to redraw all). The build sets `page.og_image` when the file exists; `base.liquid` falls back to `emblem-og.jpg`. The cards are committed (about 5 MB): Cloudflare only runs `npm run build`.
- **Home performance rules** (the site lagged badly before): the panel width animates (`flex-grow`), so nothing inside may be resized or repainted per frame. Images, `.panel__shade` and `.panel__scrim` have a fixed width (`max(80vw, 100%)`); dimming is the image's `opacity`, not a CSS `filter`; no container queries; text blocks have their own layers; pointer handlers go through `pointerFrame()` (one layout read per frame) and never set inherited custom properties. Measure with `node scripts/bench.mjs http://localhost:4000/ label ["css to inject"]` (headless Edge via DevTools protocol: fps, long frames, main-thread time). Reference on the home page: 42 fps / 16 long frames before the fixes, ~58-60 fps / 1-4 after.
- **Live data**:
  - `[data-live="<Title>"][data-field="version|size|archives|updated"]` is filled from `https://raw.githubusercontent.com/Alaxouche/Wunduniik/main/modlist.json`, which holds all 5 lists, CORS OK, 10-minute `sessionStorage` cache.
  - `[data-fresh]` shows "Updated" when the update is less than 45 days old.
  - Discord: `[data-discord-online]` / `[data-discord-count]` via `discord.com/api/guilds/750268919201398805/widget.json`.
  - In production both come from `/api/live` first (one request), the two URLs above are the fallback.
- **Docs**:
  - sidebar where the current page lists its h2s (`[data-side-toc]`);
  - reading bar (`[data-progress]`);
  - "Step n / N" bar;
  - copyable section anchors, code copy buttons;
  - zoomable images, lightbox with navigation;
  - **section icons**: `build.mjs` (`SECTION_ICONS`) gives each h2 a `data-icon` from its id (EN and FR slugs: install, antivirus, page file, update, ENB…); the star stays the fallback. Icons are CSS custom properties `[data-icon="x"] { --i: url(svg) }` at the end of `site.css`;
  - **glossary tooltips**: `_data/glossary.yml` (terms, regexes, EN/FR definitions). `glossarize()` in `build.mjs` wraps the first occurrence of each term per page and per language block in `.gl` (dotted underline, tooltip on hover / focus / tap, Escape closes, bubble kept inside the window by `site.js`). Guide pages only (not changelogs or load orders) plus the FAQ blocks of `/faq/` and `/hub/`; never in headings, links, code, tables (they scroll sideways and would clip the bubble) or the drawn widgets. Runs after the search index is built. Add a term by adding an entry: keep definitions short and true.
  - **No "already read" marks and no step tick boxes**: both were removed at the user's request (Nov 2026), do not add them back. `site.js` clears the old `taf-read` / `taf-ticks` keys.
- **Modlist overview pages** (built in `build.mjs`): the "Quick Links" / "Liens Rapides" lists are replaced by cards (`quickCards()`, built from the real nav, with live version on the changelog card), the "Key Features" / "Fonctionnalités Clés" bullets (`- **Title**: text`) become alternating text / screenshot rows (`featureRows()`, pictures from the page's `gallery_path`), and `doc.liquid` adds an "Install X" call-to-action strip (`.doc-cta`) at the end.

## Editorial preferences (from the user)

- Modern, cinematic, "unique" design. Inspirations: https://zenematics.com (split-panel home, docs at `/zenderal/docs/`; the user calls it "zenderal.com", which does not resolve) and Ivy's Workshop https://itzivy05.github.io/Workshop/index.html (light nav with one CTA, diagonal hero, alternating feature rows, CTA strip). **Don't copy them**: keep the Astral Forge identity (forge, stars, gold, the emblem).

## Shell pitfalls hit on Windows

- The accent-stripping regexes in `site.js` / `build.mjs` contain the literal characters U+0300–U+036F. That's intentional; they work.

## Performance rules (measured with Lighthouse in Nov 2026, keep them)

- Compared with Ivy's Workshop / Lumina (GitHub Pages) under the same simulated mobile and gzip: home 92 vs 77, guide 94 vs 99, changelog 93 vs 98 (mobile); desktop changelog 97 vs 80, guide 97-98. Before the fixes, Ezoic alone cost 0.5 to 1.2 s of blocking time on mobile.
- The LCP element is the hero image: **no opacity in entrance animations** of `.phero__bg` / `.phero__inner` (transform only).
- **No infinite animation that repaints**: the grain is static, the live dot ring is a transform/opacity pseudo-element, remaining loops (panel drift, molten bar on the open panel, hint star) are compositor-only.
- **Nothing may be inserted above content after load (CLS)**: changelog summaries/badges, the open latest version and the search bar (`changelogStatic`) and relative dates (`reltime` filter) are rendered by `build.mjs`; `site.js` only wires them. Heading anchors are absolutely positioned. Closed changelog versions use `content-visibility: auto`.
- Measure: `npx --yes lighthouse@13.6.0 <url> --preset=desktop` with `CHROME_PATH` set to Edge (see "Verifying visually"), against `npx --yes serve@14.2.8 _site -l 5050` (gzip like GitHub Pages; the dev server doesn't compress). To block a host, pass one `--blocked-url-patterns=` flag per pattern.

## Mod contents, authors wall, install estimator (Nov 2026)

- **Data**: `scripts/modlist-contents.py` reads each list's published `.wabbajack` straight from `authored-files.wabbajack.org` (2 MB parts + `definition.json.gz`): only the zip index, the `modlist` entry and the profiles' `modlist.txt` are fetched (~15 MB for Wunduniik instead of 430 MB). Output `_data/contents_<id>.json`: version, profile (the one with the most enabled mods), `groups` (MO2 sections `02. ____ NAME ____` > sub-separators `02.1 NAME`, each with mods `[folder, author, nexus url, bytes]` in MO2 order), `authors` (Nexus `Author` split on `,` `&` `and`; the list author is excluded), `downloads` per source (game files excluded). Separator names are cleaned (numbering and rulers removed, capitals turned into Title Case with `KEEP` acronyms). A local file can be passed for an unpublished build, but the site should show the published one.
- **Contents page** `_<id>/contents.md` (`{{ modlist.id | contents_map }}`, nav 1.7, quick card "Mod Contents" with the chart icon): squarified treemap computed in `scripts/contents.mjs` for 4 layouts (disk space / mod count x wide 16:10 / phone 2:3), positions as CSS vars in %, labels fitted by `site.js`; clicking a block or a row of the section list loads `/assets/data/contents-<id>.json` into the panel. `changelogStatic` only runs on `/changelog/` URLs (this page has `<details>` too).
- **Authors wall** `/authors/` (`authors.md`, `{{ site.modlists | authors_wall }}`, footer link): top 12, A-Z grid with search and list chips (`?list=<id>`), a `<dialog>` with the author's Nexus pages per list from `/assets/data/authors.json`.
- **Install estimator** on the 5 Wabbajack install pages, section "How Long Will It Take?" (`{{ modlist.id | install_estimator: 'en' }}` in each language block). Assumptions in `_data/install_estimator.yml` (Nexus free caps 3 / 1.5 MB/s from help.nexusmods.com, one click per Nexus file without Premium, install MB/s per drive type: rough, printed under the widget). Same formula in `estimate()` (contents.mjs) and `site.js`; choices kept in `localStorage['taf-est']`.

## Troubleshooting, updating, legal (Nov 2026)

- **Troubleshooting page** per list `_<id>/troubleshooting.md` (nav 3.5, quick card "help" icon): guided questions `{{ modlist.id | troubleshooter }}` from `_data/troubleshoot.yml` (nodes, `only:` list ids or games skyrim/cyberpunk/nms/starfield; every answer repeats a fix already in the guides), crash log section per game, and the reader `{{ modlist.id | crash_reader }}` (not on NMS: no crash logger). Renderer `scripts/troubleshoot.mjs`; links name a page title (+ heading) and `resolveLink` in build.mjs turns them into URLs and heading ids exactly as the Markdown renderer makes them (marked escapes `'` to `&#39;`, hence ids like `problemes-d39installation`). A missing page drops the link, a missing heading drops the anchor.
- **Crash log reader** (`site.js`): structured logs (Crash Logger SSE / Trainwreck: `PROBABLE CALL STACK`, `POSSIBLE RELEVANT OBJECTS`, `REGISTERS`, `STACK` weighted; `MODULES`/`PLUGINS` ignored; page file and RAM use from `SYSTEM SPECS`; GPU driver DLLs in the call stack) or, for Cyberpunk, only the error/warning lines of RED4ext, redscript and CET logs. File names map to mods through `/assets/data/files-<id>.json` (key files per enabled mod, highest MO2 priority wins, from `modlist-contents.py`). Tested on real Trainwreck and redscript logs. Facts: Skyrim lists use Crash Logger (`Documents\My Games\Skyrim Special Edition\SKSE\crash-*.log`), ECP Trainwreck (`...\Starfield\SFSE\Crashlogs\`), GotG has Advanced Crash Reporter **disabled** and "Disable CrashReporter" enabled, so its logs are in `overwrite\red4ext\logs`, `overwrite\r6\logs\redscript_rCURRENT.log`, `overwrite\bin\x64\plugins\cyber_engine_tweaks\`.
- **Updating the List** `_<id>/installation-guide/updating.md` (nav 5.5). Based on Wabbajack's `FileDeletionRules.cs` (4.3.2.2): an update deletes every file of the install folder not in the list except the downloads folder, the `.wabbajack`, anything under `profiles\<profile>\saves`, paths with a `[NoDelete]` folder, and BSAs that need no rebuild; since 4.2.0.0 a "Confirm file deletion" window asks first. Skyrim lists have `LocalSaves=true` (saves inside the list folder), the other three keep saves in the game's usual place.
- **Legal page** `/legal/` (`legal.md`, footer link): anonymous non-professional publisher (art. 1-1 II LCEN since the SREN law of May 2024), host Cloudflare Inc. (address and phone from its SEC filings), browser storage keys, third parties, bug form data. Update it when a storage key, a third-party request or the bug form changes.
