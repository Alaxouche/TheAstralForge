# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Documentation site for Alaxouche's Wabbajack modlists (theastralforge.com). There are five lists: Wunduniik and Krentoraan (Skyrim SE), Ghost of the Grid (Cyberpunk 2077), No Man's Sky Explorer, and Extrasolar Containment Protocol (Starfield). All content is bilingual EN/FR.

The site was **rebuilt in November 2026**. It no longer uses Jekyll. A small Node generator now reads the old Jekyll content (Markdown, YAML, Liquid) unchanged. The site owner (Alaxouche) speaks French; other contributors work in English. Answer in the language the person writes in. `README.md` is the short human introduction; this file holds the detail.

## Current goal: a design of its own

The November 2026 rebuild took its look from Zenematics (https://zenematics.com, source in the sibling folder `../zen-site-v1/` when it is checked out; read-only reference, never edit it). The goal now is to make The Astral Forge look like itself. What was borrowed, measured by comparing the two stylesheets:

- **Palette**: the same near-black `#07080a`, bone white `#ece9e2` and muted gold (`#c9a96e` here, `#c9ab76` there).
- **Type**: a Futura-style geometric sans (Jost here, Futura PT there; `futura-pt` is still in the `--font` fallback stack), set in wide-tracked uppercase for titles, labels and buttons.
- **Home** (replaced by the forge on Nov 21 2026): the hover accordion of full-height image panels (`flex-grow` 1 to 7, idle label / vertical label / full content, scrim and shade, bottom bar). The class names are the same: `.panel`, `.panel__idle`, `.panel__vert`, `.panel__full`, `.panel__scrim`, `.panel__shade`, `.panel__bar`, `.panel__mark`, `.panel__logo`, `.panel__title--metal`.
- **Components**: outlined rectangular buttons with one solid bone primary (`.btn`), the eyebrow label with a small mark (`.eyebrow`, `.eyebrow-row`), the docs sidebar (`.side`, `.side__group`), `.chip`, `.tags`, `.pager`, `.kb`, `.faq__item`, the YouTube facade (`.yt__play`).

**Decision (Nov 21 2026): Alaxouche chose direction A, "Struck metal"** (the forge taken literally: warm iron, brass, edges fresh from the fire), out of three mocked directions (A Struck metal, B Star atlas, C Lattice). Implemented:

- Palette: warm iron near-blacks, ash / bone text, brass `--gold` (the token kept its name), `--brass-2` polished brass for kickers over images, `--heat` / `--heat-v` gradients used **only** on the slanted seams, the molten bar, the reading bar, the current step and callout edges. Every former gold literal is now `rgba(var(--gold-rgb), a)`.
- Type: titles in Cormorant Garamond, normal case (no more wide-spaced capitals); kickers and eyebrows in brass serif italic; small labels in Alegreya Sans capitals at .08em at most. A script pass removed every `letter-spacing` over .1em.
- Parts: `.btn` is a plate with one cut corner (`--plate` clip-path, clip removed on `:focus-visible` so the ring shows), solid buttons in polished brass with an arrow; home panel stats are a strip of "hallmark" plates; the docs sidebar is a numbered ledger (current page shows the star); callouts have a cut corner and a hot left edge; FAQ and changelog versions are serif.
- **The logo is unchanged and must stay so** (the user asked explicitly): emblem plus "THE ASTRAL FORGE" in Jost capitals. The mock's gold italic "Astral" was refused.
- Generated images follow the palette: `make-hexfield.py` (warm iron tile faces, brass and heat glow, backgrounds `#0d0a08` / `#f2ece3`) and `make-og.py` (STYLE 4: Cormorant title, brass italic kicker, heat bar; the wordmark stays Jost) were updated and rerun on Nov 21 2026, thumbnails rebuilt. The 404 tile outlines did not change (same geometry). `make-emblem.py` was left alone: its app icons and `emblem-og.jpg` keep the old `#07080a` background, because the logo files must not change without asking.

**Decision (Nov 21 2026): the home page is now "the forge"** (proposal 1b of six home layouts, then made quieter at rest, see "Home: the forge"; the user turned down keeping the Zenematics-style slides, so the slanted panels, their seams and `.panel__*` are gone). One screen of scroll per section: The Forge, then the five lists. Each section is struck in on a 3D anvil: one hammer swing, the list's emblem as a brass medallion lying on the anvil face (orange-hot, then cooling), the next background opening as a honeycomb from the point of impact (decided Nov 21 2026, replacing a plain circle: the edge is whole hexagons, the tiles at the front glow brass and orange, then cool), the title decoding in runes, the line under it typing out, the numbers counting up. Copy on the left half, anvil on the right (phone: anvil in the upper half). The side menu is the six emblems; clicking one strikes straight to that section, nothing in between. Details in "Front end" below. Assets: the anvil and the hammer are 3D models generated with Artlist / Higgsfield (Tripo H3.1, 1,500 credits; the hammer from an earlier generated picture, 860 credits for the scene tests), saved in the user's Artlist folder "Astral Forge anvil"; the raw GLB files are too big to commit. Still borrowed after this pass: the eyebrow and sidebar structure. What is already The Astral Forge's own and should lead the next steps: the emblem (circle and sword), the 4-point star, the honeycomb fields, the modlist emblems, the forge home, the rune decoding of titles, the molten bar, the light theme, the two languages, the live data.

## Commands

```bash
npm install          # liquidjs, marked, js-yaml (dev deps only)
npm run dev          # build + server on http://localhost:4000, rebuilds when files change
npm run build        # one-off build into _site/ (also refreshes _data/modlist_snapshot.json from the live modlist.json)
npm run check        # checks _site/: internal links/images/srcset exist, every <img> has alt, no hotlinked image
npm run thumbs       # python scripts/make-thumbs.py: 480 / 960 / 1600 px WebP (1600 at quality 85) + manifest (Pillow); run after adding images
npm run og           # python scripts/make-og.py: social preview cards in assets/og/ (after a build; run again when pages are added or renamed)
npm run hex          # python scripts/make-hexfield.py: the honeycomb backgrounds (numpy + Pillow), then npm run thumbs
npm run contents     # python scripts/modlist-contents.py [id] [local .wabbajack]: _data/contents_<id>.json from the PUBLISHED lists; run after each list release
python scripts/supporters.py <patreon members.csv> <kofi supporters.csv> _data/contributors.yml   # rewrites recent / top supporters from the two exports (Patreon USD, Ko-fi EUR; e-mails only used to match people, never written)
npm run shot -- <page> [out.png] [options]   # screenshot of the local site in a given state (see "Verifying visually")
npm run bench -- http://localhost:4000/ label   # frame rate of the home forge strikes (see "Home performance rules")
```

- There are **no unit tests and no linter**. `npm run check` (on the built `_site/`) is the only automated gate; it blocks pull requests through `quality.yml`.
- The `npm run thumbs / og / hex / contents` scripts call `python`. On a Windows machine where `python` is only the Microsoft Store stub, run the script with the launcher instead: `py scripts/make-thumbs.py`.
- Project skills and agents live in `.claude/`: skills `visual-check`, `astral-identity`, `modlist-release`; agent `design-reviewer`.

- **The dev server does not reload `scripts/build.mjs`.** After editing that file, restart the server. On Windows, the old Node process often keeps port 4000 (`EADDRINUSE`). Free it with:
  `netstat -ano | grep ":4000 " | grep LISTENING` then `taskkill //PID <pid> //F`.
- Changes to templates, CSS, JS and content trigger an automatic rebuild (~0.8 s). Builds are **incremental**: `_site/` is never wiped, files are only written/copied when they changed, and anything the build didn't produce is deleted at the end (`pruneOut`). So a test file dropped in `_site/` disappears at the next rebuild. Builds never overlap (a change during a build queues one more).
- `site.version` (the `?v=` on site.css/js) is a hash of `site.css` + `site.js`, not a timestamp.
- `site.css` / `site.js` are minified by esbuild (dev dependency, exact version 0.28.2) when written to `_site/`; edit the readable sources in `theme/assets/`. `theme/static/_headers` sets Cloudflare Pages cache rules (patterns must not overlap: Cloudflare joins the values). The inline `<head>` script and `site.js` carry `data-cfasync="false"` so Cloudflare Rocket Loader cannot delay them (it made the language and theme switch after the first paint).
- Ruby/Jekyll is not installed and is no longer needed.
- Deployment: `.github/workflows/pages.yml` (Node 22, `npm ci`, thumbnails with Python + Pillow, `npm run build`, `npm run check` as a non-blocking report, uploads `_site/`). On pull requests: `quality.yml` (build + blocking `npm run check` + non-blocking lychee for external links) and `lighthouse.yml` (build, http-server, Lighthouse on home / overview / guide / changelog / FAQ). All three were moved off Jekyll in Nov 2026; `images.yml` (size budget) and `gallery-sync.yml` (weekly Discord sync) are unchanged.
- The first build after starting the dev server can take 3 to 50 s on this machine: the profile shows it is disk wait on G:, the build itself is about 1 s of CPU. Don't chase it as a code regression.

## Build-specific behaviour

- Layout mapping (`layoutFor`): `skyground_home` → home, `page` → page, everything else → doc.
- kramdown is emulated: `markdown="1"` is removed (CommonMark handles HTML blocks itself), and `{: .note }` / `{: .warning }` etc. become `.callout callout-*` (on the paragraph or the following blockquote).
- Heading ids are slugified with de-duplication. The `# h1` in the content is **hidden by CSS**; the doc layout shows its own title.
- Each modlist's front matter (`_<id>/index.md`) supplies `game`, `project_banner.{image, accent, subtitle, subtitle_fr, stats}`, and optionally `project_banner.image_position_phone` (CSS `object-position` of the home forge background on phones, for a subject off centre: No Man's Sky uses `92% 50%` for the astronaut). The build exposes this as `site.modlists[]` with `nav` and `live` (fallback values taken from `_data/modlist_snapshot.json`).
- **Live data at build time**: `liveModlists()` fetches the live `modlist.json` once per process (8 s timeout, `TAF_OFFLINE=1` skips it) and refreshes the snapshot in memory, so the HTML carries current versions, sizes and dates. `npm run build` also rewrites `_data/modlist_snapshot.json` when it changed; the dev server never writes it (it would trigger a rebuild).
- The `Loading...` placeholders (`data-modlist-total/install/download`) are filled in at build time from the snapshot, with the unit as `GB`/`Go` spans. Sizes in stats are a bare number (`m.live.size`) followed by the unit spans, so the live update and the count-up only touch the number. The "Mods" stat is `modlist.mods`: `totals.mods` of `_data/contents_<id>.json`, else the front matter stat.
- **Thumbnails**: Liquid filters `{{ src | thumb: 480 }}` and `{{ src | srcset }}` read `assets/Images/_thumbs/manifest.json` and fall back to the original when a thumbnail is missing. Used by the screenshot grid (480), feature rows and the community gallery (960; the lightbox still opens the original through `data-zoom`), and `srcset` on the home panels, hub bands and page heroes.
- **YouTube**: `youtubeFacade()` turns `youtube.com/embed/<id>` iframes into a link with the local thumbnail `assets/Images/guides/yt-<id>.webp`; `site.js` swaps in a `youtube-nocookie` player on click. A new video needs its thumbnail saved there (otherwise the link shows without a picture).
- The `FR` dictionary in `build.mjs` translates titles and labels. Liquid filter `bi` → `<span lang="en">…</span><span lang="fr">…</span>`.
- `step` (guide page n / total) is computed from the parent page and its children (`parent: Installation Guide`). `step.items` carries `{title, url}` for the step bar labels.
- A first `h2` that repeats the page title (e.g. "System Requirements" under "System Requirements") gets `class="is-dup"`: hidden by CSS, skipped by the outline and anchors.
- Doc subpages use a compact hero (`.phero--compact`); only the modlist overview keeps the full-height one.

## Front end

- **Language**: `html[data-lang]` hides `[lang="en"|"fr"]` blocks. Choice stored in `localStorage['sg-lang']`, browser language by default. Every interface string must exist in both: `<span lang="en">…</span><span lang="fr">…</span>`. Attributes can't hold spans: put English in the attribute and French in `data-ph-fr` (placeholder), `data-aria-fr` (aria-label) or `data-title-fr` (title); `localizeAttrs()` in `site.js` swaps them.
- **Accessibility** (last CSS layer "Readability & accessibility"): text tokens meet WCAG AA (`--dim` 4.7:1, `--muted` 6.2:1, don't darken them), body weight 400, 2px gold focus ring (inset on `overflow: hidden` boxes), `prefers-reduced-motion` stops all loops, `prefers-contrast: more` and `forced-colors` handled. Mobile menu and docs sidebar go through `overlay()` in `site.js` (Escape, focus in/out, Tab trap, `aria-expanded`). Search announces its result count in `#search-status`. `.sr-only` exists for screen-reader-only text.
- **Theme**: dark by default, plus a light theme (Nov 2026) chosen with the sun / moon button next to EN/FR (`[data-theme-toggle]`, `localStorage['taf-theme']`, applied by the `<head>` script before paint, `html[data-theme]`). It does not follow the OS setting: dark stays the house look. How it works: translucent colours are rgb-triplet tokens (`--ink` lines/glass, `--paper` scrims, `--txt` soft text, `--white` strongest text, `--logo-filter`), and the last CSS layer redefines every token for `:root[data-theme=light]`. Image areas stay dark islands (they reset the dark tokens): the home forge, `.phero`, hub bands, `.doc-cta`, `.cta`, lightbox, video thumbnails, and the nav while it floats over a dark hero. **New CSS must use the tokens, not literal `rgba(255,255,255,…)` / `rgba(7,8,10,…)` / `#fff`**, or it breaks in light. Palette and fonts are the "Struck metal" ones (see "Current goal" above): dark `--bg #0d0a08`, `--gold #d6a24e` (brass), light `--bg #f2ece3`, `--gold #7a571b`; contrast of every text token is written next to it in `site.css`. Fonts are self-hosted in `theme/assets/fonts/` (latin + latin-ext woff2, SIL OFL, `OFL*.txt`): **Cormorant Garamond** for titles and kickers (`--serif`), **Alegreya Sans** for text, labels and buttons (`--font`), **Jost** only for the wordmark next to the emblem (`--brand`). Each has a fallback `@font-face` resized to its metrics (fontTools, `scripts/make-fonts.py` prints the values) so the swap does not move the page. The latin Alegreya Sans 400 and Cormorant files are preloaded. No Google Fonts. **One colour for every modlist**: the build sets `modlist.accent` to `var(--gold)` (the per-list colours were removed at the user's request, Nov 2026; `project_banner.accent` in front matter is ignored). **No dash rule** before "Version" on the home panels.
- **Logo**: the emblem (circle + sword). Browser tab icon: `favicon.svg` (transparent, fills the square, white in a dark browser theme and dark in a light one through `prefers-color-scheme` inside the SVG) + `favicon-32.png` fallback; app icons (`emblem-180/192/512.png`) keep the dark background. All made by `make-emblem.py`. Source in `assets/source/emblem-source.png` (not deployed), assets regenerated with `python scripts/make-emblem.py assets/source/emblem-source.png assets/logos`: `emblem.webp` (large) and `emblem-mark.webp` (nav/footer), both transparent and lossless, `emblem-180/192/512.png` (apple-touch, manifest) and `emblem-og.jpg` (social card), white on the site background. The source is rendered with a glow: the script keeps only the solid strokes (luminance >= 252). **The user wants the plain logo, no glow, halo or drop-shadow**, in files and in CSS. The old `theastralforge.*` files are no longer referenced by the theme.
- **Visual identity** (asked for by the user, keep it): 4-point star (`.diamond` / `.star` via `clip-path`) instead of diamonds, rune decoding of titles (`[data-scramble]`), film grain (static since Nov 2026, `body::after`), animated "molten metal" bar. **No cursor halo**: removed at the user's request, do not add it back. **No roman numerals** on the home panels (I, II… and "Modlist II" labels), removed at the user's request (Nov 2026).
- **Modlist emblems** (Nov 2026): `scripts/make-modlist-emblems.py` draws `assets/logos/emblems/<id>.svg` in the site emblem's language (thick ring broken where the motif crosses it, plain white, no glow): Wunduniik snowy mountain with three pines standing on the ring and the North Star, Krentoraan tower, Ghost of the Grid broken grid with a glitched ring, NMS planet and orbit, ECP hexagonal field with clamps and the site star. The build sets `modlist.emblem`; the home forge strikes it onto a medallion and uses it in the side menu.
- **No particles**: the user asked (Nov 2026) to remove the ember / spark effects completely (first a Canvas 2D version, then a WebGL one). Do not add particle effects back unless asked. **Exception (Nov 21 2026, asked for by a contributor, not yet seen by Alaxouche):** one burst of sparks when the hammer hits the medallion on the home forge (`burst()` in `forge.js`: 90 additive points with short trails, gravity, gone within a second; nothing at rest, none with reduced motion). Remove it if the owner objects.
- **Home: the forge** (`theme/layouts/home.liquid`, CSS layer "Home: the forge" at the end of `site.css`, module `theme/assets/forge/forge.js`):
  - Markup: `.forge` (`data-forge`, `data-hero` so the nav floats over it) > `.forge__pin` (sticky, one screen) holding the backgrounds (`.forge__bg`, the hex field then each list's `project_banner` image), the canvas, the fallback emblem (`.forge__mark`), six `.forge__slide` articles (both languages, live `data-live` fields, `data-count`, `data-scramble`) and the emblem rail (`.forge__rail`: a row along the bottom with each list's name on desktop, names hidden below 1180 px; a strip on the right on phones; plain links to each list without the script). The module adds `.is-live` (the track becomes `--n` screens tall), `.is-3d` once the scene has drawn, `.is-flat` without WebGL2.
  - At rest (decided Nov 21 2026, after "the hammer and anvil just sit there"): the hammer is out of frame, the anvil is dark, shrunk to 80 %, sunk and nearly transparent, and the section's medallion stands up facing the viewer at the place and size of the stand-in emblem `.forge__mark` (CSS: desktop right 16vw, centred, `min(26vw, 340px)`; phones centred at 30 % height, `min(46vw, 220px)`); `setRest()` takes that element's screen box. A strike (1.5 s): the old medallion lies back on the anvil as the anvil rises and lights up, the hammer comes in and swings once, then leaves; the new medallion rises; the anvil fades back. The floor shadow is off.
  - Background reveal (`hexReveal()` in `forge.js`): the next picture is clipped to a CSS `path()` rebuilt each frame (one circle for the tiles well behind the front, plus each tile of the front band, growing from its centre, with a steady per-tile jitter so the edge is ragged); the glowing tiles are drawn on the 2D canvas `.forge__heat`, above the dimming layer and under the 3D canvas. Tile radius `min(W, H) / 22` clamped to 22-46 px, 1.15 s. Costs about 0.4 ms of script per frame, only during a strike.
  - `forge.js` = a WebGL2 renderer (no library) + the page controller. It draws only during a strike or a resize; idle costs nothing. Start-up waits for `load` + an idle moment, compiles shaders in the background (`KHR_parallel_shader_compile`) and builds each emblem texture on demand (canvas compositing, no pixel loops), so it never blocks long; `performance.mark('forge:*')` times each step. The one step that cannot be split is creating the WebGL context: about 7 ms with a GPU, about 230 ms in Lighthouse's software rendering, which costs the home about 10 Lighthouse points (mobile perf ~63-71, accessibility 100, CLS 0; it was ~79 with the panels).
  - Text effects reuse `scramble()` and `countUp()` from `site.js` (exposed as `window.TAF`); the typewriter is in `forge.js` and keeps the untyped text in place (transparent), so nothing moves. `prefers-reduced-motion`: no swing, no reveal, sections just swap.
  - Models: `py scripts/make-forge-models.py <anvil.glb> <hammer.glb>` writes `theme/assets/forge/*.bin` + WebP. The anvil is simplified to 24k triangles with per-vertex colours (simplifying scrambles the source's UV atlas); the hammer keeps full detail and textures, its head repainted in the anvil's iron. The medallion is made in code. About 730 KB, loaded after first paint, cached 30 days (`/assets/forge/*` in `_headers`; `forge.js` carries `?v=` and is part of `site.version`).
  - The dark-island rule covers `.forge` (it stays dark in the light theme) and `.home-legal`.
- **Honeycomb backgrounds** (asked by the user, Nov 2026), all from `scripts/make-hexfield.py` (variants listed in `VARIANTS`): `forge-hex-dark` is the first home background (`forge-hex-lit`, `forge-hex-light`, `forge-hex-light-lit` are no longer used since the forge home; kept until the user decides). `hex-hero.webp` is the hub header and the overview CTA strip, `hex-void.webp` (missing tiles) the 404 header, each with a `-light` twin: these honeycomb banners follow the theme (they are not dark islands in light; `.theme-d` / `.theme-l` classes show the current theme's picture, the light one is lazy). `page_hero.html` takes `hex=true` (class `.phero--hex`, no extra dimming) and `image_light`. ## Verifying visually

There's no Playwright. `scripts/shot.mjs` drives headless Edge / Chrome over the DevTools protocol (shared launcher in `scripts/browser.mjs`, also used by `bench.mjs`; it finds the browser in `Edge/Application`, `EdgeCore/<version>/` or Chrome, or takes `CHROME_PATH`). The dev server must be running.

```bash
node scripts/shot.mjs home out.png --panel 1            # home with panel 1 open (0 = The Forge); a hover can't be captured, the script sets .has-on / .is-on
node scripts/shot.mjs wunduniik/ --mobile --theme light --lang fr   # real 390 px phone viewport at 2x, light theme, French
node scripts/shot.mjs hub/ --full --still               # whole page, reduced motion (entrances settled)
node scripts/shot.mjs wunduniik/installation-guide/ --matrix        # dark + light x desktop + mobile, four files
```

- Without an output path the PNG goes to `<tmp>/taf-shots/` and the path is printed. Other options (`--at "selector"`, `--js "code"`, `--w`, `--h`, `--wait`) are in the header of the script.
- **In Git Bash, write page paths without the leading slash** (`hub/`, `home` for the root): Bash turns `/hub/` into `C:/Program Files/Git/hub/`. The script undoes the common case, but don't rely on it.
- Every visual change must be looked at in **both themes and at phone width** before it is called done: `--matrix` is the quick way. The `visual-check` skill has the full routine.

## Shell pitfalls hit on Windows

- `cat <<'EOF'` heredocs containing apostrophes sometimes fail in this Bash. Use the Write tool, or a file in the scratchpad that gets `cat >>`-ed.
- The accent-stripping regexes in `site.js` / `build.mjs` contain the literal characters U+0300–U+036F. That's intentional; they work.
